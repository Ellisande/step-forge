2. ~~Hooks~~ — DONE. Side-effect-only hooks (never seed state — the dependency graph stays the source of truth), registered via plain functions from the main entry. Three scopes: `beforeScenario`/`afterScenario` (get `{ world, scenario }`, run inside `runScenario`; after-hooks always run, LIFO), `beforeFeature`/`afterFeature` (Vitest `beforeAll`/`afterAll` in the generated describe, once per feature file), and `beforeAll`/`afterAll` (truly-global). Global is once-_per-worker_ (a `globalThis`-guarded `ensureGlobalHooks` in the generated describe) — same realm as steps so it can touch in-process state, but teardown is best-effort on the worker's `beforeExit`. A true once-per-run globalSetup was rejected: Vitest resolves `globalSetup` to real paths before plugins run, and it executes in a separate realm.
3. ~~Source maps~~ — DONE. On a failing step, `runScenario` prepends a synthetic stack frame pointing at the `.feature` file (`file:line:column`, above the real step-definition frames) instead of jamming `file:line` into the error message. Because the frame's file is the real feature on disk, Vitest treats it as a source location and renders a code frame at the failing step, with the true throw-site stack preserved below. Hook failures have no step to point at, so they surface with their own stack unchanged. See `attachFeatureFrame` in `src/runtime/engine.ts`. A static transform source map was not needed: the failing-step location is dynamic (which step threw is known only at runtime), so a synthetic runtime frame — not a compile-time map of the generated module — is the mechanism that actually points at the right line.
4. ~~Delete the Cucumber adapter + `@cucumber/cucumber` dep~~ — DONE. The adapter/try-catch is already gone from `common.ts` (its `execute` is runner-agnostic). The last raw-Cucumber consumer was `features/steps/analyzerSteps.ts` (the analyzer self-tests), which has been ported to the native builder pattern: the two `Given`s record fixture paths in world state, `When I analyze the files` runs `analyze()` and produces `{ diagnostics }`, and each `Then` reads them via a `when.diagnostics` dependency (`features/steps/analyzerWorld.ts` holds the state contract). `features/analyzer/analyzer.feature` now runs through the Vitest plugin — `vitest.config.ts` lists `features` as **exact** files so the analyzer's `fixtures/*.feature` (inputs to `analyze()`, not tests) are never discovered; the plugin's `features` option now accepts `string | string[]` for this. `cucumber.mjs`, the `@cucumber/cucumber` dependency, and the `@cucumber/pretty-formatter` devDependency are all removed. (`@cucumber/gherkin`, `@cucumber/messages`, and `@cucumber/cucumber-expressions` — the standalone libraries — stay.)
5. Parser/ParameterType unification — parsers currently re-coerce on top of cucumber-expression captures (works because they tolerate both); folding Parser<T> into a ParameterType is still open.
6. ~~Tags (@skip/@only) and scenario-outline labels~~ — DONE. `gherkinParser` now records each scenario's effective `tags` (feature + rule + scenario, plus the Examples-block tags for outline rows) on `ParsedScenario`. The Vitest plugin maps them onto the runner: `@skip` → `test.skip`, `@only` → `test.only` (skip wins if both). Scenario-outline rows carry `outline.name`, and the plugin groups consecutive rows from one outline under a `describe(<outline name>)` with a `test` per row labelled by its example values (`amount=100, currency=USD`), so each row is independently addressable and can carry its own `@skip`/`@only` — strictly more expressive than a single `test.each`. Covered by `features/tags.feature`.
7. ~~Plugin root via `process.cwd()`~~ — DONE. `stepForge()` has a `configResolved(config)` hook that sets `root = config.root`; `process.cwd()` is only the pre-config initializer. Vite runs `configResolved` before any `transform`/`resolveSteps`, so step-glob resolution always uses the real Vite root.
